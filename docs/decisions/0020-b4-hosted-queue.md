# 0020 — B4: hosted queue (connect, dispatcher, queue ETA, supervisor, Vercel)

**Status:** accepted · 2026-10-27

## Decision
- The GPU machine runs the worker as an outbound-only `inngest/connect` client in prod (`maxWorkerConcurrency: 1`, `instanceId` = `ADFORGE_WORKER_ID`, our own shutdown owns the signals); prod never opens a listening port, while dev keeps `serve()` on 127.0.0.1.
- Two Inngest apps, because one app id is synced as a whole by whichever endpoint registers it: `adforge-gpu` (generate-ads, heavy-*, product-ingest, variant-edit/export, gpu-idle) via connect; `adforge-web` (dispatcher, janitor) served by the Vercel web app at `/api/inngest` so they run while the GPU machine is offline. Events, event-id dedupe and env-scoped concurrency are environment-wide, so cross-app triggering and the single heavy lane still work.
- The Inngest client's dev/cloud mode follows ADFORGE_ENV; `.env` is loaded by an import-first module and the worker refuses to start if the client mode does not match the env. Prod requires INNGEST_SIGNING_KEY and INNGEST_EVENT_KEY.
- Heartbeat: every 30 s the worker upserts a `workers` row (migration 0019) with SQL `now()`; a clean stop sets only status 'offline'; `online_since` (migration 0021) marks the start of a continuous online stretch. Freshness is judged on the database clock only.
- The dispatcher (cron each minute + `adforge/dispatch.nudge` on submit) is the only sender of `adforge/job.requested` in prod (the dev-only local route sends it directly). While a heartbeat is fresh it claims up to 10 oldest queued jobs with FOR UPDATE SKIP LOCKED and sends each with event id `job:<jobId>` inside ONE transaction (per-send 5 s timeout, `idle_in_transaction_session_timeout` 60 s); a crash rolls the claim back and Inngest's 24 h event-id dedupe drops a re-send.
- While offline it sends nothing and fails every queued job older than 24 h with "GPU offline for 24 h". The janitor fails a silent running job only after staleAfterMin of continuous online time. generate-ads' load step no-ops on a job that is no longer queued/running (a failed job is never revived). generate-ads finish timeout is 6 h; no start timeout (a start-timeout cancel skips onFailure).
- Migration 0020 tightens the restrictive INSERT policy on jobs: members can insert only queued, undispatched jobs whose created_at is within one minute of now() (no queue-jumping by backdating).
- Edit and export events carry `priority: 'interactive'`, which the heavy functions turn into a higher Inngest run priority than queued jobs; product-ingest instead runs at a fixed run priority of 600.
- Queue status is a query: position = 1 + queued/running jobs created before this one (all orgs counted, only numbers returned, called only after the user's RLS read). ETA uses p50/p90 of completed jobs in the last 30 days with the same language and b-roll setting (fallbacks: all completed jobs, then 900 s); a queued job adds the running jobs' remaining time; a running job shows its own remaining range; "paused" when no fresh heartbeat. No JS Date is ever passed into SQL.
- The supervisor is `scripts/supervisor.ps1` started by a logon scheduled task the user installs with `scripts/install-supervisor.ps1` (no admin, no third-party binary); it starts ComfyUI, voice, voice-qwen, vision and the worker, restarts them per policy (exit-3 for the Python services), and stops by stop file or Ctrl-C. Worker logs are JSON lines in `<ADFORGE_DATA_DIR>/logs`, rotated daily (UTC), 14 kept, secrets redacted by key name.
- Web on Vercel: Supabase transaction pooler (:6543) with prepare:false; statement timeout 15 s set per transaction inside withUser (Supavisor transaction mode rejects session SET); prod requires an https ADFORGE_SITE_URL; the Vercel build command stays the package `build` script; Vercel Preview deployments use the DEV environment (dev Supabase, adforge-dev bucket, Inngest branch env with INNGEST_ENV unset).
- Amendments to the roadmap: the B4 e2e is GPU-free (jobs dispatch, show position/ETA, pause, resume and fail fast at preflight with ComfyUI off); submission no longer sends job.requested; `workers` is owner-only (no user grants); a scheduled task instead of NSSM; the Vercel deploy is its own task.

## Consequences
- Queued jobs wait in Postgres (not Inngest) while the GPU is offline and resume within a minute of the heartbeat returning.
- Renaming the GPU app to `adforge-gpu` renamed its Inngest function ids (prefixed by app id); harmless before launch.
- Owner-connection queries outside withUser are bounded only by Supabase's 2-minute global cap for the postgres role; a dedicated web login role with its own statement_timeout is the upgrade path.
- Killing the supervisor process itself orphans its children (no Job Object); the stop file or Ctrl-C is the clean stop.
- The dispatcher, janitor and gpu-idle crons are about 60k Inngest runs a month before steps — check the plan quota at launch.
- Steps after generate-ads' load step still write status unconditionally (a run continuing after the janitor failed its job could overwrite 'failed'); recorded for a later fix.
