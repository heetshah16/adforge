# Cloudflare R2 (S3 API) — provider notes

Fetched 2026-10-19 from developers.cloudflare.com (r2/api/s3/api, r2/api/s3/presigned-urls, r2/buckets/cors, r2/buckets/bucket-locks) and the aws4fetch README (github.com/mhart/aws4fetch, pinned 1.0.20).

## Endpoint
- `https://<ACCOUNT_ID>.r2.cloudflarestorage.com/<bucket>/<key>` (path style; the AWS CLI emits this). SDKs may emit `<bucket>.<ACCOUNT_ID>...`; we use path style.
- Region is `auto` (required by S3 signers, unused by R2). Service `s3`.
- Presigned URLs work only on the S3 API domain, not custom domains.

## Operations we use
- PutObject, HeadObject, GetObject: implemented.
- PutObject does NOT support: ACLs, `x-amz-object-lock-*`, tagging, website redirect, SSE other than SSE-C, lifecycle. Storage classes: STANDARD, STANDARD_IA only.
- Conditional headers (`If-None-Match` etc.) supported on PUT/HEAD/GET; PUT conditions are atomic (`If-None-Match: *` race -> loser gets 412). We HEAD-then-PUT (content-addressed, so a race writes identical bytes).
- Content-Type is stored as system metadata on PUT and returned by HEAD/GET.

## Presigned URLs
- Expiry: 1 s to 7 days (604 800 s). Methods: GET, HEAD, PUT, DELETE (no POST).
- A URL is reusable until it expires: treat it as a bearer token.
- Content-Type: if signed (included in SignedHeaders), a PUT with a different value fails 403 SignatureDoesNotMatch.
- **Content-Length: the docs say nothing about whether R2 enforces a signed Content-Length on a presigned PUT.** Do not rely on it. Size limits must be enforced by the server (mint-time declared size, then re-validation of the stored object by HEAD/read in the worker, Task 5). Not live-verified.
- Expired URL -> 403 without CORS headers, so a browser cannot read the error body; refresh before expiry.

## CORS (bucket)
Dashboard shape is a bare array; wrangler's `--file` shape wraps rules in `{"rules":[...]}` with origins/methods nested under `allowed` (check which your tooling expects).
- Browser presigned PUT needs: `AllowedOrigins` exact origin, `AllowedMethods` PUT (we add GET/HEAD), `AllowedHeaders` every header the client sends (`Content-Type`), optional `ExposeHeaders: ["ETag"]`, `MaxAgeSeconds` (browsers may cap ~2 h).
- Apply: `npx wrangler r2 bucket cors set <bucket> --file cors.json`; verify with `cors list`.

## Bucket locks
- Rules: age (`maxAgeSeconds`), date, or indefinite; optional key prefix; up to 1000 rules; longest retention wins.
- Locked objects cannot be deleted OR overwritten during retention. Applies to existing objects. Overrides lifecycle rules. Bucket cannot be emptied while rules exist.
- Consequence for us: content-addressed puts are idempotent, so HEAD-first (skip PUT when present) is required, otherwise a re-put into the locked prod bucket would fail.
- Commands: `wrangler r2 bucket lock add|set|list|remove <bucket>`.

## aws4fetch 1.0.20
- `new AwsClient({ accessKeyId, secretAccessKey, service, region, retries })`. `retries` defaults to **10** (retries 5xx/429 with backoff): we set `retries: 0` and own retry/timeout policy.
- `aws.sign(url, { method, headers, body, aws: { signQuery, datetime, allHeaders } })` returns a signed `Request`. `datetime` form `20150830T123600Z`. `signQuery: true` puts the signature in the query string.
