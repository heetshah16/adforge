# B3: Media on R2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** prod media lives in a private R2 bucket. Keys are tenant-prefixed. The GPU worker reads through a local disk cache. Browsers upload straight to R2 with presigned PUTs and view media through app-minted signed GETs on our own domain. Dev keeps local disk.

**Architecture:**
- **R2Storage** (`packages/providers/r2`, aws4fetch SigV4) implements `StorageProvider` and adds presign/head.
- **Org scope.** The org that owns a `put` comes from an `AsyncLocalStorage` scope. That scope is set once per Inngest handler, so providers and their request types stay org-agnostic. A `put` outside a scope throws in prod.
- **CachedStorage** wraps R2 on the worker.
- **The web app** mints uploads (`POST /api/uploads`) and serves `GET /media/[...key]` as a 302 to a short-lived signed R2 URL, after a membership check on the key's org.
- **The worker** re-validates and re-encodes every upload with sharp before first use.

**Tech Stack:** TypeScript, aws4fetch 1.0.20, sharp 0.35.5 (already in the lockfile via Next; prebuilt `@img/*` binaries, no build script), Next.js 16.3.8 route handlers, Inngest 4.21.1, Zod 4, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-17-poc-to-prod-bridge-design.md` §5.1, §5.3 and §5.8, plus the roadmap `docs/superpowers/plans/2026-10-17-bridge-roadmap.md` §B3, whose fixed interfaces this plan honours. The amendments are listed below.

## Amendments to the roadmap (ADR 0018 records them)

1. **R2 has no bucket versioning.** The R2 S3 API lists `PutBucketVersioning` as unimplemented. Backup protection is a **bucket lock rule** on the prod bucket instead: no delete or overwrite for 30 days. Keys are content-addressed and immutable, and app code never deletes. The roadmap's T1 "enable bucket object versioning" is replaced by this.
2. **`POST /api/uploads` returns `{ key, url, headers }`** (a presigned **PUT**, the headers the browser must send), not `{ url, key, fields }`. `fields` belongs to S3 POST policies, which R2 does not support for presigning.
3. **The e2e is GPU-free.** By the user's rule (2026-10-19), the full `e2e:pipeline` waits until the end of development. `pnpm e2e:r2` covers:
   - a presigned upload with a CORS preflight;
   - normalization;
   - a 240×426 5-frame render through `CachedStorage(R2Storage)`;
   - `/media/*` redirects and a cache-hit second render;

   all against the dev bucket and dev Supabase. No ComfyUI, TTS or LLM.
4. **The upload size cap is raised from 5 MB to 10 MB per photo,** so phone JPEGs fit. The dimension cap is 8192 px per side, and the pixel limit is 50 MP.

## Global Constraints

- **Provider boundaries:**
  - provider SDK types never leave `packages/providers/<name>/`;
  - everything crossing a boundary is a `MediaRef` or a type from `packages/core/src/providers/types.ts`;
  - every provider request is Zod-validated before dispatch.
- **`MediaRef.url` is always `StorageProvider.urlFor(key)`.** In prod that is `${ADFORGE_PUBLIC_URL}/media/<key>`, our route, never an R2 hostname.
- **Prod storage keys** are `org/<orgId>/<2-hex>/<sha256>.<ext>`. Dev keys stay `<2-hex>/<sha256>.<ext>`.
- **Pins and dependencies:**
  - pin exact versions at least 14 days old (aws4fetch 1.0.20 is from 2024-08-28; sharp 0.35.5 is in the lockfile), never ranges, and never `minimumReleaseAgeExclude`;
  - a dependency build script needs an explicit `allowBuilds` entry. sharp 0.35 needs none, so if pnpm asks, stop and report.
- **New providers follow CLAUDE.md:** docs into `docs/providers/r2.md` first, one recorded live response, a golden request, and an honest registry/env entry.
- **Tests:**
  - `pnpm test` passes before every commit, with no network, no GPU and no subscription;
  - R2 is faked with an in-memory `fetch` in tests;
  - render tests are 240×426, 5 frames.
- **Liveness:** every outbound R2 call has a timeout (`R2_TIMEOUT_MS`, default 30 000), which becomes `ProviderError('TIMEOUT', retryable)`.
- **Tenancy:**
  - a key's org must equal the caller's org on every path (upload mint, job create, media GET);
  - a `put` outside an org scope throws in the R2 provider.
- **Secrets:**
  - R2 credentials live only in the gitignored `.env` (worker) and the web's `.env.local` / Vercel env;
  - never print or commit them, and never send them to the browser.
- **Git:**
  - commit with `git -c user.name=heetshah16 -c user.email=shahheet85@gmail.com` and a `Co-Authored-By` trailer naming the implementing model;
  - stage specific paths only;
  - never commit `.env*`, `fixtures/eval-products/`, `.superpowers/` or media;
  - push only after the milestone's final review.
- **Workflow:** an ADR (`docs/decisions/0018-b3-media-on-r2.md`) for every decision the specs didn't dictate.

## Review Focus

1. **A foreign-org key on any path:** a key minted for org A, presented by a member of org B, at `POST /api/jobs` or `GET /media/*`. Expected: 403, no asset row, no redirect. Tested in Task 4 and Task 6.
2. **A storage `put` with no org scope in prod:** a new Inngest function or a script forgets the scope. Expected: R2Storage throws `missing storage org scope` and never writes an unprefixed object. Tested in Task 1 (scope) and Task 2 (provider).
3. **A hostile or odd upload:** HEIC, CMYK JPEG, a 40 MB PNG, a polyglot, EXIF GPS, a 9000×9000 PNG, a truncated file. Expected: rejected with a clear message, or re-encoded to sRGB with metadata stripped. Tested in Task 4 (mint-time size/type) and Task 5 (decode/normalize).
4. **A signed URL expiring mid-review:** a video plays past the signed GET's TTL and a seek fails. Expected: the player re-requests `/media/<key>` and resumes at the same time, at most 3 times. Tested in Task 6.
5. **A cache key that escapes the cache directory:** `org/../../x` or a backslash on Windows. Expected: `CachedStorage` rejects anything that isn't a `StorageKey` before touching disk. Tested in Task 3.

### E2e: `pnpm e2e:r2` (Sonnet writes it, the controller runs it once)

`apps/worker/src/e2e-r2.ts` runs with `ADFORGE_ENV=prod`, the dev Supabase `DATABASE_URL` and `R2_BUCKET=adforge-dev`. It needs no GPU, no LLM and no Inngest. It:
1. Mints an upload for the operator org (the handler logic with that org's user), sends an `OPTIONS` preflight with `Origin: http://localhost:3000`, and PUTs the eval photo with the returned headers.
2. Normalizes the photo and `put`s it inside `withStorageOrg`, through `CachedStorage(R2Storage)` with an empty cache dir.
3. Renders a 240×426, 5-frame spec that uses the normalized photo as a plate, through `HyperframesRenderer`, with the same storage. FFmpeg must be on the PATH.
4. Calls the media handler with the owning user (expects a 302 to an R2 host; fetching it returns the mp4 bytes) and with a user of another org (expects 403).
5. Renders again, counting `inner.read` calls.

**Pass:**
- the preflight allows the origin;
- every `urlFor` result starts with `ADFORGE_PUBLIC_URL/media/`;
- no `r2.cloudflarestorage.com` appears in any `MediaRef.url`;
- the cache dir has the photo and the mp4;
- the second render does 0 inner reads;
- 302 for the owner and 403 for the stranger;
- no processes left running.

The report goes to the plan's SDD workspace as `e2e-report.md`.
