# P3–P8 Roadmap — from media factory to reviewed ads

**Date:** 2026-10-16
**Spec:** [2026-10-15-adforge-local-poc-design.md](../specs/2026-10-15-adforge-local-poc-design.md), with **§11 amendments**
**Status of earlier milestones:** P0, P1 and P2 are merged to `main`.

This roadmap plans every remaining milestone: scope, task breakdown, the interfaces between milestones, the tests each task carries, and the single end-to-end check that closes each milestone. The **code-level plan for each milestone** (writing-plans format, complete code, TDD steps) is written immediately before that milestone is implemented. Two reasons:
1. CLAUDE.md requires fetching the vendor's real docs first.
2. Each milestone's real interfaces feed the next.

Every code-level plan must honour the interfaces fixed here, or amend this file first.

## Testing rule (all milestones)

- **Every task:** functional tests (unit and integration) in `pnpm test`, with no GPU, no network and no subscription. They use recorded fixtures, fakes and golden files.
- **Every milestone:** exactly **one end-to-end check**, run once at the end of the plan. It is a live script or a browser run, named below. It is not in `pnpm test`.

## Liveness rule (all milestones): nothing hangs, idle resources are freed

The user requires this; it binds every plan.
- **Every outbound call has a timeout:**
  - ComfyUI client: 30s per request (exists).
  - TTS service: per-request timeout.
  - Claude Agent SDK `query`: an `AbortController` with a deadline per call.
  - Whisper: a per-clip deadline.
  A timeout is a retryable `ProviderError('TIMEOUT')`, never a silent wait.
- **Every long operation has a deadline and is cancellable:**
  - HyperFrames render: `executeRenderJob(..., abortSignal)` with a per-render deadline that kills the browser/FFmpeg children on abort.
  - ComfyUI jobs: `syncTimeoutMs` / `queueTimeoutMs` (exist).
  - Video poll loop: an overall deadline.
  - Each Inngest step: a timeout configured on the function.
- **Idle TTL on every model holder:**
  - The TTS service unloads Chatterbox after `TTS_IDLE_TTL_S` (default 120s) without requests.
  - The Whisper pipeline is disposed after its batch, or after an idle TTL if it is held in-process.
  - ComfyUI gets `POST /free` at batch boundaries, and from the janitor below.
- **Janitor:** an Inngest cron function (P7) runs every 5 minutes. When no heavy step is running, it:
  - frees ComfyUI;
  - unloads TTS;
  - **reconciles stale work**, i.e. any `provider_calls` row `pending` for longer than 2× its typical latency gets polled or failed (architecture §10);
  - marks jobs with no progress past their deadline as `failed`, with the reason.
- **Child processes:** every spawned process (Chrome, FFmpeg, Python service) is killed on abort, timeout or parent exit. Long-running services expose `GET /health`, and the pipeline's `preflight` fails fast if a service is unhealthy.
- **Tests:** each plan includes at least one test proving a hung dependency becomes a timeout error, using a fake that never responds plus a short deadline.

## P3 — Render: VideoSpec → MP4 via HyperFrames

**Goal:** a hand-written `VideoSpec` renders to a 20 s, 1080×1920, 30 fps MP4 containing:
- a generated plate with the **real cutout composited on top**, both under one motion, with a drop shadow;
- one b-roll segment;
- word-by-word burned-in captions;
- a voice track;
- an on-screen claim.

**Docs first:**
- the local HyperFrames source at `~/.claude/plugins/cache/hyperframes/hyperframes/<ver>/packages/producer` (`createRenderJob`, `executeRenderJob(job, projectDir, outputPath, onProgress, abortSignal)`);
- the `hyperframes-core`, `hyperframes-captions` / `embedded-captions` and `hyperframes-audio` skills;
- the result goes into `docs/providers/hyperframes.md`.

**Pin** `@hyperframes/producer` (and `core` if needed) to an exact version **at least 2 weeks old** (0.x, about 2 releases a day).

**Interfaces fixed here** (consumed by P6 and P7):
- `packages/core/src/spec/video-spec.ts`: the Zod `VideoSpec`, from app-spec §5.3 adapted to the POC:
  - `fps: 30`, `width`, `height` and `durationInFrames`.
  - `scenes[]`, each with `startFrame` and `durationInFrames`. Layers are a discriminated union:
    - `plate`: `{ key, motion, fit }`
    - `cutout`: `{ key, anchor, scale, shadow }`, sharing the scene's motion
    - `video`: `{ key, trimStartFrame, durationInFrames, muted }`
    - `text`: `{ content, position, weight, scrim, enterFrame, exitFrame }`
  - `audio.voice[]`: `{ key, startFrame, durationInFrames }`
  - `captions.words[]`: `{ text, startFrame, endFrame, emphasis? }`
  - `theme`: `{ fontFamily, primary, accent, captionStyle }`
- **Asset references are storage keys** (`MediaRef.id`, e.g. `ab/<sha>.png`), never URLs. This closes carry-forward item #9: "assetId" in CLAUDE.md means the storage key, and the renderer resolves keys through `StorageProvider`.
- `RendererProvider` in core: `render({ spec, idempotencyKey }) → Promise<ProviderResult<MediaRef>>`.

**Tasks:**
1. **`VideoSpec` schema plus invariants.** Scenes are contiguous and their frames sum exactly; layer frames fall inside their scene; caption words are ordered and non-overlapping; keys are storage-key shaped. **Tests:** valid and invalid specs, and a property test that `layoutFrames` output always validates.
2. **Composition generator.** Pure function `VideoSpec → { html, variables }`, using HTML/CSS/GSAP per the HyperFrames conventions. It covers: motion presets (`slow_zoom_in/out`, `slow_pan`, `subtle_shake`, `static`) applied identically to plate and cutout; cutout anchoring with a CSS drop shadow; text overlays; and word-caption markup. **Tests:** golden HTML per motion and layer type; the variables payload validated against the generated JSON Schema (CLAUDE.md HyperFrames rule).
3. **Asset staging.** Copy the spec's keys from storage into the render project dir, and **resolve fonts locally** (bundled font file; CLAUDE.md trap: tofu). **Tests:** a missing key fails before render; the font file is present.
4. **`renderer-hyperframes` provider.** Stage, `createRenderJob`, `executeRenderJob`, then put the MP4 into storage and return a `MediaRef`. Idempotent per key. **Tests:** the CLAUDE.md render test at **240×426, 5 frames**; it needs headless Chrome and FFmpeg but no GPU or network, so it runs in `pnpm test`. If the producer's toolchain proves too slow for `pnpm test`, the task records a ruling.
5. **Hand-written sample spec plus ADR 0008:** the HyperFrames adapter, the version pin, the asset-key decision, and the composition conventions.

**End-to-end check:** `pnpm e2e:render` builds a 4-beat sample spec from the P2 smoke outputs (plate, cutout, b-roll) plus a placeholder voice WAV. It renders 1080×1920×20 s, then prints the MP4 path, duration and frame count. **Pass:** the file plays, it lasts exactly 600 frames, the cutout stays visually locked to the plate under motion, and the captions are readable.

**Carry-forward closed:** #9 (asset id) and the T4 note "trim b-roll to the planned frames" (the `video` layer carries its own `durationInFrames`).

## P4 — Vocabulary shortlist + diversity assertion

**Goal:** the deterministic shortlist (spec §6, rules layer) and `assertVariantDiversity` at **family** level. These are the code-enforced half of the "not a wrapper" claim.

**Docs first:** none (internal).

**Interfaces fixed here:**
- `packages/core/src/vocab/registry.ts`: `type Registry = { archetypes, formats, hooks, families }` as plain data, loaded once from the DB by `loadRegistry(db)` in `packages/db`.
- `shortlist(brief: { archetypePrimary, archetypeSecondary }, registry, cfg = PIPELINE.shortlist)`. It returns `{ formats: Ranked[], hooks: Ranked[], experimental: Ranked | null }` with `Ranked = { slug, family, score, reason }`. The function is pure, deterministic, and only offers `active` entries plus at most one reserved `experimental` slot. It never offers `retired`.
- `assertVariantDiversity(variants: { hookSlug, formatSlug }[], registry, cfg = PIPELINE.diversity)`. It returns `Violation[]` (empty means OK); each violation names the rule, for example "2 hooks share family `tension`". It is pure.

**Tasks:**
1. **`loadRegistry` (db) plus the `Registry` type (core).** **Tests:** against seeded PGlite; retired rows excluded from `active`, included in `bySlug`.
2. **`shortlist`.** It scores the affinity of `fitsArchetypes` against the primary and secondary archetypes; `[]` means fits any; slug order breaks ties so the result is deterministic. **Tests:** fixed briefs give snapshot rankings; the experimental slot is honoured when an experimental row exists and empty otherwise; retired rows never appear; the same input always gives the same output.
3. **`assertVariantDiversity`.** **Tests:**
   - 3 distinct hook families passes.
   - 3 distinct hook slugs spread over only 2 families fails, which is the near-synonym case the rule exists for.
   - 1 format family fails.
   - An unknown slug is a violation.

**End-to-end check:** `pnpm e2e:shortlist`. Against the real seeded DB in `C:/adforge-data`, it prints the shortlist for 3 archetype pairs (remedy+trust, indulgence+identity, utility+upgrade) and runs the diversity check over a hand-picked passing and failing trio. **Pass:** the shortlists differ visibly by archetype and the failing trio is rejected with a named reason.

## P5 — LLM layer: Strategist + Director (Claude Agent SDK)

**Goal:**
- `strategize()` classifies a product by buying psychology from its photos and text.
- `direct()` returns 3 variants **chosen only from the shortlist**, diverse at family level, with one repair pass that names the violation.

**Docs first:**
- Agent SDK TypeScript reference: `query()` options for model, effort, disabling tools / single turn, image content in the prompt (streaming input), `outputFormat`, and the result and error subtypes;
- usage and cost fields on the result message, and prompt caching behaviour under the SDK.

The result goes into `docs/providers/claude-agent-sdk.md`. Pin `@anthropic-ai/claude-agent-sdk` exactly.

**Interfaces fixed here:**
- `LLMProvider` in core: `generate<T>({ system, user: (Text | Image)[], schema: ZodType<T>, model, effort, idempotencyKey }) → Promise<ProviderResult<{ value: T; usage }>>`. Provider id `claude-agent-sdk`; an API-key provider can slot in later.
- Env: `ADFORGE_PROVIDER_LLM=claude-agent-sdk`, `ADFORGE_LLM_STRATEGIST` / `ADFORGE_LLM_DIRECTOR` (model ids; replacing the OpenRouter slug format) and the existing effort vars.
- `packages/core/src/llm/`: `StrategistOutput` and `DirectorOutput` Zod schemas. The Director's beat fields are: `beat, vo, overlay, scene, product_prominence, duration, motion, emotion` (`emotion` is new and drives Chatterbox `exaggeration`), plus per-variant `language` and `strategic_bet`.
- `packages/core/src/prompts/*.md`: byte-frozen system prompts from build spec §6–7, adapted:
  - the 3-language block (en / hi / hinglish);
  - the shortlist and the numeric rules rendered into the **user** message, after the cache boundary, from `PIPELINE`.

**Tasks:**
1. **`LLMProvider` adapter over the Agent SDK.** **Tests:** a fake `query` stream covering success with `structured_output`, `error_max_structured_output_retries`, success without structured output, and Zod re-validation failure. All map to the right `ProviderError` codes. Plus a golden file of the options object sent.
2. **Prompts plus `strategize()`.** **Tests:** a golden rendered user message; the system prompt contains no product, job or date interpolation, which is required for caching.
3. **`direct()`** with the shortlist-only constraint enforced in code: a slug outside the shortlist is a violation. The repair pass reruns once with the named violations, then fails. **Tests:** fakes returning a diverse set (passes), a 2-family set (repair, then passes), a repeat failure (fails with violations), and an off-shortlist slug (repair).
4. **Hook rules in code:** at most `PIPELINE.hook.maxWords` words and `maxChars` characters, the banned openers, and no brand name in the hook. Violations feed the same repair pass. **Tests:** table-driven.

**End-to-end check:** `pnpm e2e:llm`. It runs strategize → shortlist → direct live on **both of the user's products**. **Pass:**
- Schema-valid output.
- Family-level diversity holds.
- Every slug comes from the shortlist.
- Hook rules hold.
- The printed rationale and the three strategic bets read as genuinely different bets (human read).

Cost and latency are printed per call.

## P6 — Voice (Chatterbox) + caption alignment (Whisper) + spec builder

**Goal:** Director output plus stored assets → a frame-exact `VideoSpec`, with voice per beat in en / hi / hinglish and word captions aligned by Whisper.

**Docs first:**
- the Chatterbox repo and model card (`ChatterboxMultilingualTTS`, the `language_id` values, `exaggeration` and `cfg`, VRAM);
- transformers.js Whisper (`@huggingface/transformers`) with `return_timestamps: 'word'`: the model choice (multilingual small or base, since Hindi needs multilingual) and CPU speed.

The result goes into `docs/providers/chatterbox.md` and `docs/providers/whisper.md`.

**Interfaces fixed here:**
- `TTSProvider` (core, from app-spec §4.4) narrowed to `synthesize({ text, language: 'en'|'hi'|'hinglish', emotion: 0..1, idempotencyKey }) → ProviderResult<MediaRef>`. The returned `durationSec` is measured from the WAV.
- `services/tts/`: a minimal Python HTTP service (FastAPI, its own `uv` venv, pinned deps) wrapping Chatterbox Multilingual, started by `scripts/tts.ps1` on `127.0.0.1:8190`.
  - **Blackwell constraint, checked 2026-10-16:** `chatterbox-tts` 0.1.7 pins `torch==2.6.0` for Python below 3.14. That version has no sm_120 support for the RTX 5070 Ti. It allows `torch>=2.9.0` only on Python 3.14 or later.
  - The service therefore uses a **Python 3.14** venv with a CUDA 12.8+/13 torch build.
  - Fallback if a dependency such as librosa or numba lacks 3.14 wheels: Python 3.12 with `torch` 2.9+ installed over the pin, recorded in ADR 0010.
  - The first step of P6 Task 1 is a GPU smoke test: `torch.cuda.get_arch_list()` contains `sm_120`, and one sentence synthesizes. The Node adapter is `packages/providers/chatterbox`. It loads the model lazily and unloads it after idle, so it can hand the GPU back to ComfyUI. The P6 plan decides whether the pipeline calls ComfyUI `/free` before a TTS batch.
- `CaptionAligner` (core): `align({ audio: MediaRef, text, language }) → { words: { text, startSec, endSec }[] }`. The implementation is `packages/providers/whisper-align`; the fallback is the existing `proportional` mode.
- `buildSpec(direction, assets, voice, alignment, cfg) → VideoSpec`. It is pure. Beat length is the larger of the planned duration and the VO duration plus the tail. Seconds become frames only through `layoutFrames`, and b-roll is trimmed to its beat's frames.
- **Hinglish handling:** Chatterbox gets `language_id='hi'` with the Latin-script text; if the listening check fails, the plan falls back to transliterating to Devanagari for TTS only. The P6 plan rules on this after the docs and a first sample.

**Tasks:**
1. **Python TTS service plus its own tests** (pytest on a 1-line synth gated behind `--live`, and a request-schema unit test). Add an ADR (0010) for the Python-service exception to "TypeScript end-to-end".
2. **Chatterbox `TTSProvider` adapter.** Zod before dispatch, golden request body, one recorded live response as a fixture (CLAUDE.md provider rule). **Tests:** fixtures plus a fake server.
3. **Whisper aligner.** **Tests:** a short committed WAV fixture with known words (en and hi) gives monotonic word timings inside the clip.
4. **`buildSpec`.** **Tests:** golden `VideoSpec` from a recorded Director output; frames sum exactly; captions sit inside their beats; b-roll is trimmed; T0 overlay on `hero`/`supporting` beats and none on `absent` (fidelity tier computed in code).

**End-to-end check:** `pnpm e2e:voice`. For one P5 direction per language (en, hi, hinglish), it synthesizes the voice, aligns it, builds the spec and renders the MP4 through P3. **Pass:** three MP4s with audible VO, captions in sync by eye, and **the user's listening check on all three languages**.

## P7 — Pipeline: Inngest end to end

> **Amended 2026-10-16 (P7 plan, ADR 0011):** the API and the Inngest functions live in **`apps/worker`** (plain `node:http` run by tsx), not in `apps/web`. Next would bundle the workspace packages that read files relative to `import.meta.url`, and PGlite is single-process. P8's Next UI proxies `/api/*` and `/media/*` to the worker. The heavy lane is four Inngest functions on one env-scoped `"heavy"` key.

**Goal:** upload → 3 MP4s with no manual steps, with durable memoized steps, safe retries, and partial success treated as success.

**Docs first:**
- Inngest: the local dev server (`npx inngest-cli dev`), `createFunction`, `step.run` memoization and serialization, retries, **concurrency keys**, `step.sleep`, and `@inngest/test`.
- Next.js route handler for `/api/inngest`.

The result goes into `docs/providers/inngest.md`. Pin exactly.

**Interfaces fixed here:**
- `apps/web` gets its first, API-only form: `POST /api/jobs` (multipart: photos plus form fields), `GET /api/jobs/:id` (job, step and variant status), `GET /media/[...key]` (storage passthrough), and `/api/inngest`. PGlite is opened once per process and cached on `globalThis` (carry-forward). The `next build` path never opens the DB.
- `packages/pipeline`: the `generate-ads` Inngest function, built from steps in spec §6:
  - preflight (ComfyUI `preflight()`, TTS health, `configSnapshot` written);
  - ingest;
  - cutout;
  - strategize;
  - shortlist;
  - direct;
  - per variant: plates → fidelity → broll (if enabled) → voice → align → buildSpec → render;
  - finalize.
- **Heavy steps share one Inngest concurrency key `heavy` with limit 1:** ComfyUI, Chatterbox **and the HyperFrames render**. VRAM is 16 GB, and system RAM is 31.8 GB, of which ComfyUI pins ~13 GB. Free RAM fell to ~4.6 GB during Wan. This extends spec §6's GPU key to cover rendering.
- **Turn-taking also releases memory, not just work.** An idle server keeps its models resident. The hand-off protocol at each batch boundary, verified against ComfyUI v0.35.1:
  - ComfyUI batch done: `POST /free {"unload_models": true, "free_memory": true}`.
  - TTS batch done: the service's `POST /unload`.
  - Alignment done: drop the Whisper pipeline reference.
  - Render: the Chrome process exits per render.
  - ComfyUI also launches with `--disable-pinned-memory`, because it otherwise pins ~13 GB of RAM even when idle. Its offload-speed cost is measured once in P7, before and after, and recorded in an ADR.
  - Release only at batch boundaries. A Flux reload from NVMe takes ~10–20 s.
- **Steps are batched by model, never interleaved per beat:**
  1. all plates and cutouts;
  2. ComfyUI `/free`, then all TTS;
  3. TTS unload, then b-roll;
  4. render.
  A Flux model swap reloads about 17 GB, so interleaving would cost minutes per job.
- **Video is one retry unit:** a failed `poll` causes `submit` with the same key (ADR 0007).
- `ProviderError` is **serialized explicitly** (`{code, message, retryable}`) before leaving `step.run` (carry-forward).
- **Idempotency keys are namespaced `jobId:step:variantNo:beat`.** A duplicate `provider_calls.idempotencyKey` means already recorded (carry-forward).

**Tasks:**
1. **Minimal `apps/web` API, `/media` route, PGlite singleton.** **Tests:** route handlers against an in-memory DB; a `/media` traversal attempt is rejected.
2. **`provider_calls` recording plus a `recordCall` helper with duplicate-key semantics.** **Tests:** double record is a no-op.
3. **The `generate-ads` function.** **Tests (`@inngest/test`, all providers faked):**
   - the happy path gives 3 variants;
   - one variant failing gives the job `completed` with a warning;
   - all variants failing gives `failed`;
   - a b-roll failure degrades its beat to plate plus Ken Burns;
   - a diversity failure after repair fails the job;
   - a retried step does not re-call its provider;
   - the GPU concurrency key is set on every GPU step.
4. **`configSnapshot` assembly** (spec §4, ADR 0006): pipeline config, treatments, workflow hashes, model ids, prompt hashes, no secrets. **Tests:** snapshot shape; no env secret values present.

**End-to-end check:** `pnpm e2e:pipeline <product-slug>`. With ComfyUI, the TTS service, the Inngest dev server and `apps/web` running, it posts one of the user's products and waits. **Pass:** 3 variants, each with an MP4 in storage, diverse at family level; `configSnapshot` and `provider_calls` populated. Run once with b-roll off; optionally once with it on.

## P8 — Review UI

**Goal:** minimal, functional pages:
- **Upload:** photos, name, price, description, language, b-roll toggle.
- **Job progress:** polls `GET /api/jobs/:id`.
- **Review:** three `<video>` players side by side, the Strategist rationale, each variant's strategic bet, format, hook and family. Approve one, download its MP4.

**Docs first:** the Next.js App Router version in use (vercel:nextjs skill) and Playwright test runner basics. Pin exactly.

**Interfaces fixed here:** `POST /api/variants/:id/approve` sets `variants.status` to an approved state. This needs a `variant_status` enum migration adding `approved`, recorded as a Drizzle migration.

**Tasks:**
1. **Upload page and form validation:** 3–5 photos, image mime types only, a size cap, required fields. **Tests:** component and route tests for each validation error.
2. **Job progress page:** step list, per-variant status, error and warning display. **Tests:** rendering from recorded job payloads (queued, running, partial, failed).
3. **Review page plus approve and download.** **Tests:** rendering with 3 variants and with 2 (partial); approve route and migration.

**End-to-end check:** `pnpm e2e:ui` (Playwright, real browser). It uploads one of the user's products through the page and waits for completion. **Pass:** 3 players play, the rationale and bets are visible, and approving one persists after reload.

**POC done at the end of P8:** spec §1 success criteria 1–6.
