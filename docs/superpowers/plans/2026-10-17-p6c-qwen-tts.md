# P6c: Qwen3-TTS spike for English — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Why:** in listening check 2 (ADR 0010), Chatterbox Multilingual's English produced gibberish at dramatic moments. The user asked to try Qwen TTS for English.

**Goal:** an A/B pair (Chatterbox vs Qwen) of the SAME Director English copy for the user's morning listening check. **No default changes.** Every language keeps `engineByLanguage = 'chatterbox'` until the user picks.

**Facts** (from github.com/QwenLM/Qwen3-TTS and PyPI, fetched 2026-10-17):
- **License and package:** Apache-2.0. PyPI `qwen-tts` 0.1.1, released 2026-02-06, `requires-python >=3.9`.
- **Pins:** it pins `transformers==4.57.3` and `accelerate==1.12.0`; its other dependencies are librosa, soundfile, sox, onnxruntime, einops, torchaudio and gradio.
- **Models:** `Qwen/Qwen3-TTS-12Hz-{1.7B,0.6B}-CustomVoice` (9 preset timbres; English natives are "Ryan" and "Aiden") and `-Base` (3-second voice clone).
- **API:**
  - `Qwen3TTSModel.from_pretrained(id, device_map="cuda:0", dtype=torch.bfloat16, attn_implementation=...)`
  - `model.generate_custom_voice(text, language, speaker, instruct?) -> (wavs, sr)`
- **FlashAttention 2 is optional;** on Windows we use `attn_implementation="sdpa"`.
- **Gaps:** Windows support is unstated, VRAM is unstated, and Hindi is not supported (irrelevant here, since this is English only).

**Architecture:**
- **`services/voice` resolved `transformers` 5.2.0 for Chatterbox,** which is incompatible with Qwen's pin. So Qwen gets **its own uv project, `services/voice-qwen`** (FastAPI on 127.0.0.1:8191).
- **It uses the same torch override** (2.12.1 / torchaudio 2.11.0, cu130 index, Python 3.13; fallback Python 3.12).
- **It copies the small liveness helpers** (`ModelSlot`, `Watchdog`, `encode_wav`) from `services/voice/voice_core.py`. ponytail: these are copied, not shared; extract a shared package if a third engine appears.
- **Endpoints:**
  - `GET /health` → `{ ok, device, cuda, sm120, loaded: { tts }, allocated_mb }`
  - `POST /synthesize` → WAV with `X-Duration-Sec`. The body is `{ text 1..500, speaker, instruct? }` (Pydantic-validated, English only).
  - `POST /unload`
- **Liveness:** an idle-TTL janitor re-checks under the lock, and the watchdog uses separate call and load budgets.
- **Node** gets a `QwenTTS` `TTSProvider` in `packages/providers/voice-service`. A routing TTS picks the engine via `PIPELINE.voice.engineByLanguage`.

## Global Constraints
- The CLAUDE.md provider rules: docs first, Zod before dispatch, a golden request body, one recorded live response.
- Exact pins at least 14 days old, plus a committed `uv.lock`.
- No sampling parameters are set in our code. Don't pass `top_p` or temperature; use the model defaults.
- Liveness: deadlines, idle unload, the watchdog, and services stopped after live runs. The user's rule is to free resources and never hang.
- `pnpm test` and both `uv run pytest -q` suites pass (non-live) before every commit.

## Task 2: the Node `QwenTTS` provider and engine routing (Sonnet)
- [ ] **Env** (`packages/core/src/config/env.ts`): `ADFORGE_QWEN_TTS_URL`, default `http://127.0.0.1:8191`, trailing slash stripped.
- [ ] **Config** (`PIPELINE.voice`):
  - `engineByLanguage: { en: 'chatterbox', hi: 'chatterbox', hinglish: 'chatterbox' }`, a Zod enum per language: `'chatterbox' | 'qwen'`;
  - `qwen: { speaker: 'Ryan', instructExpressiveAbove: 0.75, expressiveInstruct: 'Speak with energy and conviction, like a confident ad voice-over.', calmInstruct: 'Speak naturally and warmly, like a friendly ad voice-over.' }`.
  - Tests are updated.
- [ ] **Provider** (`packages/providers/voice-service/src/qwen.ts`):
  - a `QwenClient` reusing the Task 2 (P6) client patterns: AbortSignal deadline, classified body reads, 400/404/413/422 → INVALID_INPUT, 5xx → UPSTREAM;
  - `qwenParams(text, emotion, cfg)` → `{ text, speaker, instruct }`, pure and golden-tested;
  - `QwenTTS implements TTSProvider` (id `qwen-tts`), which Zod-validates the request (English only; another language → INVALID_INPUT) and stores the WAV via storage like `ChatterboxTTS`.
- [ ] **Routing:** `createVoiceProviders` gains an optional `qwenBaseUrl`. Its `tts` becomes a router that sends each request to the engine in `cfg.voice.engineByLanguage[req.language]`; `'qwen'` without `qwenBaseUrl` → INVALID_INPUT. `unload()` unloads both (best-effort) and `health()` reports both.
  - **The router's `id` stays `chatterbox` when the defaults are unchanged.** Keep `tts.id` deterministic per config, and document it.
- [ ] **Fixtures:** `src/record-fixtures.ts` gains a Qwen recording; record one live `/synthesize` response into `fixtures/qwen-synthesize.live.json` (duration and byte count only). Start and stop `voice-qwen` for it.
