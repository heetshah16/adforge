# P8: Review UI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** minimal, functional pages:
- **Upload:** photos, name, price, description, language and the b-roll toggle.
- **Live job progress.**
- **Review:** three players side by side, with the Strategist's rationale and each variant's strategic bet, format, hook and families. **Approve one** and download its MP4.

This closes the POC (spec §1 success criteria 1–6).

**Architecture:**
- **`apps/web`** is a Next.js 16 App Router app with client components only. It talks **directly to the worker** at `NEXT_PUBLIC_WORKER_URL` (`http://127.0.0.1:3001`). The worker sends `Access-Control-Allow-Origin` for the UI origin. A multipart POST and a body-less POST are CORS "simple requests", so no preflight is needed.
- **No proxying through Next:** Next caps proxied request bodies, and uploads reach about 25 MB.
- **No server code in Next and no imports of server packages.** Media plays straight from the worker's `/media/<key>`, because `ADFORGE_PUBLIC_URL` becomes the worker URL.
- **Pure view logic lives in `lib/view.ts`,** unit-tested in Node. The page components stay thin.
- **One Playwright e2e** drives the real browser end to end.

**Tech Stack:**
- `next` **16.3.8**, `react` / `react-dom` **19.3.0**, `@playwright/test` **1.63.0**.
- **`typescript` 5.9.3 in `apps/web` only.** Next's build uses the TypeScript JS API, which TS 7's native compiler may not expose. The rest of the repo stays on 7.0.2.
- Zod 4, Vitest 5.

**Spec:** [spec](../specs/2026-10-15-adforge-local-poc-design.md) §1, §6 (UI), §11 (minimal UI). **Roadmap:** P8 section, amended by ADR 0011 (the worker owns the API). **Next.js docs:** App Router (`'use client'`, `useParams`, `next.config.ts`). Before writing pages, use the installed `vercel:nextjs` skill for Next 16 specifics.

## Global Constraints

- **The UI never touches the DB or server packages.** Its only data source is the worker HTTP API, and every worker response is Zod-parsed in `lib/api.ts`.
- **Upload limits mirror the worker:** 3–5 photos, png/jpeg/webp, each ≤ 5 MB, plus required name, price and description and a language of `en` | `hi` | `hinglish`. Client validation is a convenience; **the worker remains the authority**.
- **Liveness in the browser:**
  - each fetch has `AbortSignal.timeout(10_000)`;
  - polling (every 3 s) stops on a terminal status or on unmount, and backs off to 15 s after errors;
  - an unreachable worker shows a banner, never a spinner forever.
- **Minimal and functional.** Plain CSS, no component library. Accessibility basics: labelled inputs, `<button>` elements, visible focus, alt text, `controls` on video.
- **Approving one variant clears any previous approval for that job.** Only `completed` variants can be approved (409 otherwise).
- **Exact pins, ≥2 weeks old.** `pnpm test` (typecheck first) before every commit. **One end-to-end check** at the end (`pnpm e2e:ui`).
- Commits: `git -c user.name=heetshah16 -c user.email=shahheet85@gmail.com commit ...` with a `Co-Authored-By:` trailer naming the authoring model.

## Review Focus

1. **The worker goes down while a job page is open.** Show "worker unreachable, retrying"; keep the last known state, back off, and recover when the worker returns. → Task 2 test (`nextPollDelay`) plus the page behaviour.
2. **A partial job** (2 of 3 variants) must render two players and one clearly failed card with its reason, not a broken grid. → Task 2 test (`variantCards`).
3. **Approving a second variant** must move the approval, so only one is approved after reload. → Task 1 test.
4. **A photo over 5 MB, or 6 photos,** must be caught before upload with a clear message; the worker would also reject it. → Task 2 test.
5. **A Hindi rationale or Devanagari text in the brief** renders correctly, with no mojibake (UTF-8 end to end). → Task 3 e2e check.

```ts
/** The UI (another origin) reads worker responses directly. Multipart and body-less POSTs are CORS "simple requests". */
export function withCors(r: Response, origin: string): Response {
  const headers = new Headers(r.headers);
  headers.set('access-control-allow-origin', origin);
  headers.set('vary', 'origin');
  return new Response(r.body, { status: r.status, statusText: r.statusText, headers });
}
```

  ```ts
      const m = new URL(req.url).pathname.match(/^\/api\/jobs\/([^/]+)\/variants\/(\d+)\/approve$/);
      const id = m?.[1] ?? '';
      const n = Number(m?.[2]);
      if (!z.uuid().safeParse(id).success || !Number.isInteger(n)) return json({ error: 'not found' }, 404);
      const [v] = await deps.db.select().from(variants).where(and(eq(variants.jobId, id), eq(variants.variantNo, n)));
      if (!v) return json({ error: 'not found' }, 404);
      if (v.status !== 'completed' && v.status !== 'approved') return json({ error: `variant ${n} is ${v.status}` }, 409);
      await deps.db.transaction(async (tx) => {
        await tx.update(variants).set({ status: 'completed' }).where(and(eq(variants.jobId, id), eq(variants.status, 'approved'), ne(variants.variantNo, n)));
        await tx.update(variants).set({ status: 'approved' }).where(and(eq(variants.jobId, id), eq(variants.variantNo, n)));
      });
      return json({ approved: n });
    },
  ```

```ts
import { z } from 'zod';

export const WORKER = (process.env.NEXT_PUBLIC_WORKER_URL ?? 'http://127.0.0.1:3001').replace(/\/+$/, '');
const T = () => AbortSignal.timeout(10_000);

const Progress = z.object({ stage: z.string(), status: z.enum(['running', 'done', 'failed', 'skipped']), at: z.string(), detail: z.string().optional() });
const Variant = z.object({
  variantNo: z.number(), formatSlug: z.string(), formatFamily: z.string().nullable(), hookSlug: z.string(), hookFamily: z.string().nullable(),
  visualTreatment: z.string(), strategicBet: z.string(), isExploratory: z.boolean(),
  status: z.enum(['pending', 'running', 'completed', 'failed', 'approved']), renderUrl: z.string().nullable(),
});
const JobViewSchema = z.object({
  job: z.object({
    id: z.string(), status: z.enum(['queued', 'running', 'completed', 'failed']), progress: z.array(Progress),
    brief: z.unknown().nullable(), error: z.unknown().nullable(), costUsd: z.number(), createdAt: z.string(), completedAt: z.string().nullable(),
  }),
  variants: z.array(Variant),
});
export type JobView = z.infer<typeof JobViewSchema>;

export async function createJob(form: FormData, fetchImpl: typeof fetch = fetch) {
  const res = await fetchImpl(`${WORKER}/api/jobs`, { method: 'POST', body: form, signal: T() });
  const body = (await res.json().catch(() => ({}))) as { jobId?: string; error?: string; issues?: Record<string, string[]> };
  if (res.status === 202 && body.jobId) return { ok: true as const, jobId: body.jobId };
  return { ok: false as const, error: body.error ?? `upload failed (HTTP ${res.status})`, ...(body.issues ? { issues: body.issues } : {}) };
}

export async function getJob(id: string, fetchImpl: typeof fetch = fetch): Promise<JobView> {
  const res = await fetchImpl(`${WORKER}/api/jobs/${encodeURIComponent(id)}`, { signal: T() });
  if (!res.ok) throw new Error(`job ${id}: HTTP ${res.status}`);
  return JobViewSchema.parse(await res.json());
}

export async function approveVariant(id: string, n: number, fetchImpl: typeof fetch = fetch): Promise<void> {
  const res = await fetchImpl(`${WORKER}/api/jobs/${encodeURIComponent(id)}/variants/${n}/approve`, { method: 'POST', signal: T() });
  if (!res.ok) throw new Error(((await res.json().catch(() => ({}))) as { error?: string }).error ?? `approve failed (HTTP ${res.status})`);
}
```

```ts
export const STAGES = ['preflight', 'strategize', 'direct', 'plates', 'broll', 'voice', 'render', 'finalize'] as const;
const LABELS: Record<(typeof STAGES)[number], string> = {
  preflight: 'Checking services', strategize: 'Reading the product', direct: 'Writing three variants', plates: 'Generating scenes',
  broll: 'AI b-roll', voice: 'Voice-over + captions', render: 'Rendering videos', finalize: 'Finishing',
};
const TYPES = ['image/png', 'image/jpeg', 'image/webp'];
const MAX = 5 * 1024 * 1024;

export function validateUpload(i: { name: string; price: string; description: string; language: string; files: { name: string; type: string; size: number }[] }): string[] {
  const e: string[] = [];
  if (!i.name.trim()) e.push('Product name is required.');
  if (!i.price.trim()) e.push('Price is required.');
  if (!i.description.trim()) e.push('A one-paragraph description is required.');
  if (!['en', 'hi', 'hinglish'].includes(i.language)) e.push('Choose a voice-over language.');
  if (i.files.length < 3 || i.files.length > 5) e.push(`Add 3–5 photos (you added ${i.files.length}).`);
  for (const f of i.files) {
    if (!TYPES.includes(f.type)) e.push(`${f.name}: use PNG, JPEG or WebP.`);
    else if (f.size > MAX) e.push(`${f.name}: larger than 5 MB.`);
  }
  return e;
}

type Row = { stage: string; label: string; status: 'pending' | 'running' | 'done' | 'failed' | 'skipped'; detail?: string };
export function stageRows(progress: JobView['job']['progress']): Row[] {
  return STAGES.map((stage) => {
    const last = [...progress].reverse().find((p) => p.stage === stage);
    return { stage, label: LABELS[stage], status: last?.status ?? 'pending', ...(last?.detail ? { detail: last.detail } : {}) };
  });
}

export const isTerminal = (s: string) => s === 'completed' || s === 'failed';
export const nextPollDelay = (errors: number) => Math.min(15_000, 3_000 * 2 ** errors);

export function variantCards(view: JobView) {
  return view.variants.map((v) => ({
    variantNo: v.variantNo,
    title: `${v.formatSlug} × ${v.hookSlug}${v.isExploratory ? ' (exploratory)' : ''}`,
    families: `${v.formatFamily ?? '?'} · ${v.hookFamily ?? '?'}`,
    bet: v.strategicBet,
    status: v.status,
    canApprove: v.status === 'completed',
    videoUrl: v.status === 'completed' || v.status === 'approved' ? v.renderUrl : null,
    ...(v.status === 'failed' ? { failureReason: 'This variant failed — see the job log.' } : {}),
  }));
}

export function briefSummary(brief: unknown): { archetypes: string; rationale: string; objection: string } | null {
  if (!brief || typeof brief !== 'object') return null;
  const b = brief as Record<string, unknown>;
  if (typeof b.archetype_primary !== 'string' || typeof b.rationale !== 'string') return null;
  return {
    archetypes: `${b.archetype_primary} + ${String(b.archetype_secondary ?? '')}`,
    rationale: b.rationale,
    objection: typeof b.core_objection === 'string' ? b.core_objection : '',
  };
}
```

```tsx
'use client';
import { useParams } from 'next/navigation';
import { useCallback, useEffect, useRef, useState } from 'react';
import { approveVariant, getJob, type JobView } from '@/lib/api';
import { briefSummary, isTerminal, nextPollDelay, stageRows, variantCards } from '@/lib/view';

export default function JobPage() {
  const { id } = useParams<{ id: string }>();
  const [view, setView] = useState<JobView | null>(null);
  const [offline, setOffline] = useState(false);
  const [notice, setNotice] = useState<string | null>(null);
  const errors = useRef(0);

  const load = useCallback(async () => {
    try {
      const v = await getJob(id);
      setView(v);
      setOffline(false);
      errors.current = 0;
      return v;
    } catch {
      setOffline(true);
      errors.current += 1;
      return null;
    }
  }, [id]);

  useEffect(() => {
    let alive = true;
    let timer: ReturnType<typeof setTimeout> | undefined;
    const tick = async () => {
      const v = await load();
      if (!alive) return;
      if (v && isTerminal(v.job.status)) return; // stop polling
      timer = setTimeout(tick, nextPollDelay(errors.current));
    };
    void tick();
    return () => { alive = false; if (timer) clearTimeout(timer); };
  }, [load]);

  async function approve(n: number) {
    try {
      await approveVariant(id, n);
      setNotice(`Variant ${n} approved.`);
      await load();
    } catch (e) {
      setNotice((e as Error).message);
    }
  }

  if (!view) return <p>{offline ? 'Worker unreachable, retrying…' : 'Loading…'}</p>;
  const brief = briefSummary(view.job.brief);
  const done = isTerminal(view.job.status);

  return (
    <>
      {offline && <div className="banner" role="status">Worker unreachable, retrying — showing the last known state.</div>}
      <h1>Job <span className="muted">{view.job.status}</span></h1>
      {brief && (
        <section>
          <h2>Strategist read</h2>
          <p><strong>{brief.archetypes}</strong> — {brief.rationale}</p>
          {brief.objection && <p className="muted">Core objection: {brief.objection}</p>}
        </section>
      )}
      {!done && (
        <ol className="stages" aria-live="polite">
          {stageRows(view.job.progress).map((r) => (
            <li key={r.stage} data-status={r.status}>{r.label} — {r.status}{r.detail ? ` (${r.detail})` : ''}</li>
          ))}
        </ol>
      )}
      {view.job.status === 'failed' && <p className="errors">This job failed: {JSON.stringify(view.job.error)}</p>}
      {notice && <p role="status">{notice}</p>}
      {view.variants.length > 0 && (
        <section className="grid" aria-label="Variants">
          {variantCards(view).map((c) => (
            <article key={c.variantNo} className="card" data-status={c.status}>
              <h3>V{c.variantNo}: {c.title}</h3>
              <p className="muted">{c.families}</p>
              {c.videoUrl ? <video src={c.videoUrl} controls playsInline preload="metadata" aria-label={`Variant ${c.variantNo} video`} /> : <p className="errors">{c.failureReason ?? 'Rendering…'}</p>}
              <p><strong>Bet:</strong> {c.bet}</p>
              <div style={{ display: 'flex', gap: 8 }}>
                <button type="button" disabled={!c.canApprove} onClick={() => approve(c.variantNo)}>{c.status === 'approved' ? 'Approved' : 'Approve'}</button>
                {c.videoUrl && <a href={c.videoUrl} download={`adforge-v${c.variantNo}.mp4`}>Download</a>}
              </div>
            </article>
          ))}
        </section>
      )}
    </>
  );
}
```

`docs/decisions/0012-ui-talks-to-worker.md`:
```markdown
# 0012 — The UI talks to the worker directly

**Status:** accepted · 2026-10-16

## Decision
- **The UI is client-only.** `apps/web` (Next 16.3.8) holds client components and has **no server code**. It reads and writes only through the worker's HTTP API (`NEXT_PUBLIC_WORKER_URL`), and parses every response with Zod.
- **No proxy through Next.** The worker sends `Access-Control-Allow-Origin: ADFORGE_UI_ORIGIN`. A multipart POST and a body-less POST are CORS simple requests, so there are no preflights. This avoids Next's proxied-body size limit, since uploads can reach 25 MB.
- **Media from the worker.** `ADFORGE_PUBLIC_URL` is the worker, so `<video>` plays from `/media/<key>` directly.
- **TypeScript 5.9.3 in `apps/web` only,** because Next's build uses the TypeScript JS API. The repo stays on TS 7.
- **Approval:** one approved variant per job; approving another moves it.
- **`variants.visualTreatment` stays `text`.** It's render-coupled, so the closed Zod enum in `packages/core` is the gate. A pgEnum would add a migration for every new treatment and catch nothing the Zod parse doesn't already catch.

## Consequences
- Moving to a hosted deployment means putting the worker behind the same origin, or tightening CORS. The UI code is unchanged.
- There is no server-side rendering of job data. That's acceptable for a local review tool.
```
